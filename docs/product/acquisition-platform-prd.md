# 微探数据采集与研究平台 PRD

- 状态：Accepted（进入渐进实施）
- 日期：2026-08-26
- 产品形态：本地优先的公众号数据采集、整理、监控与研究工作台
- 相关架构：[可插拔 Provider 架构](../architecture/pluggable-provider-architecture.md)
- 相关决策：[ADR 0002](../adr/0002-adopt-pluggable-acquisition-providers.md)

## 1. 背景

当前产品按“公众号—文章列表—文章详情”的页面结构持续叠加抓取能力。文章正文、互动数据、公众号分页、微信自动化、缓存、标签、导出和分析逐渐互相耦合，使用户必须理解数据来自哪里、微信是否要打开窗口、为什么需要等待以及失败后该做什么。

用户真正关心的不是抓取技术，而是能否简单、可靠地完成三类数据任务，并在拿到数据后继续筛选、分析和监控。

## 2. 产品目标

微探应让用户只描述数据需求，由系统自动选择和组合可用的数据来源：

1. 给定文章链接，获取文章内容。
2. 给定文章链接，获取文章互动数据。
3. 给定公众号名称或 ID，分页同步公众号文章列表。
4. 把采集结果组织为可复现的数据集，并交给 Agent 分析。
5. 为公众号建立持续监控，在出现新文章时自动执行后续工作流。

## 3. 非目标

第一阶段不追求：

- 立即移除或重写所有现有抓取实现。
- 让用户在普通流程中理解 Cookie、fakeid、XWorker 或微信窗口结构。
- 一开始就支持任意第三方代码以动态库形式注入主进程。
- 用单一 Provider 覆盖所有公众号、内容类型和互动字段。
- 将桌面应用拆成微服务或引入不必要的云端基础设施。

## 4. 核心对象

### 4.1 数据资源

- **公众号 Account**：规范身份、名称、简介、头像和多来源身份映射。
- **文章 Article**：规范文章身份、链接、类型、发布时间和所属公众号。
- **正文版本 Content Version**：HTML、Markdown、媒体和抓取时间。
- **互动快照 Metric Snapshot**：阅读、点赞、推荐、分享、留言、收藏及其观测时间。

### 4.2 工作对象

- **采集任务 Acquisition Job**：一次用户数据诉求。
- **Provider 尝试 Provider Attempt**：某个 Provider 对任务的一次执行。
- **同步范围 Sync Coverage**：分页游标、日期范围、内容类型和是否已同步到底。
- **数据集 Dataset**：固定文章集合或可动态刷新的保存筛选。
- **分析任务 Analysis Run**：输入数据集、Agent、模板、输出和引用。
- **监控订阅 Monitor**：公众号、频率、同步策略和后续动作。

## 5. 核心用户旅程

### 5.1 文章内容

1. 用户粘贴一篇公网文章链接。
2. 系统识别文章与公众号身份。
3. 默认获取正文；用户可同时勾选互动数据。
4. 系统优先返回已有的新鲜结果，否则自动选择 Provider。
5. 文章进入资料库，界面展示数据来源、抓取时间和字段完整度。

用户不需要先进入公众号，也不需要选择具体抓取技术。

### 5.2 文章互动数据

1. 用户在文章详情或批量选择中点击“更新互动数据”。
2. 默认策略为“自动选择最佳来源”。
3. 后台 Provider 优先；只有确实需要前台微信时才提前提示。
4. 任务可以在用户离开当前页面后继续。
5. 缺失字段保持未知，不写成零。
6. 所有结果必须通过文章身份校验才能持久化。

### 5.3 公众号文章同步

1. 用户输入公众号名称、ID 或任意已知文章链接。
2. 系统解析并让用户确认公众号身份。
3. 用户选择：
   - 最新 N 篇、日期范围或尽可能完整；
   - 图文、贴图、视频或全部类型；
   - 仅索引、同时抓正文、同时补互动数据；
   - 单次同步或持续监控。
4. 系统创建可恢复任务，持续分页并保存 checkpoint。
5. 用户可随时暂停、继续或取消，不丢失已完成页面。
6. 结果明确展示覆盖日期、已发现数量、正文覆盖率、互动数据覆盖率及是否已同步到底。

### 5.4 数据集与 Agent 分析

1. 用户按公众号、标签、作者、日期、类型、正文状态和互动指标筛选文章。
2. 用户可保存为：
   - 动态集合：以后自动纳入符合条件的新文章；
   - 冻结数据集：固定文章与正文版本，保证分析可复现。
3. 用户选择分析模板或输入问题。
4. Agent 读取数据集并生成带文章级、段落级引用的结果。
5. 分析结果可继续追问、导出或作为监控流程的后续动作。

## 6. 信息架构

一级导航建议收敛为：

### 6.1 采集

- 一个统一输入框，识别文章链接、公众号名称和公众号 ID。
- 三个明确意图：文章正文、文章互动、公众号同步。
- Provider 选择放在高级设置，默认不打扰用户。

### 6.2 资料库

- 公众号、文章、正文版本、互动快照。
- 统一搜索、筛选、批量操作和数据质量视图。

### 6.3 数据集与分析

- 标签、保存筛选、冻结数据集。
- 分析模板、Agent 选择、分析历史和引用回链。

### 6.4 任务与自动化

- 正在执行、等待用户、部分完成、失败和已完成任务。
- 公众号监控、定时同步和后续工作流。

### 6.5 数据源设置

该入口位于设置中，不占据主导航。展示 Provider 的：

- 当前可用性和认证状态；
- 支持的能力与字段；
- 后台执行能力和前台副作用；
- 最近成功率、字段完整率和耗时；
- 成本、额度和最近验证时间。

## 7. Provider 选择体验

默认选项为“自动选择”。高级策略包括：

- 后台优先；
- 速度优先；
- 完备率优先；
- 低成本优先；
- 禁止操作微信前台；
- 禁止发送到第三方；
- 指定某个 Provider。

如果自动策略必须调用会抢占前台的 Provider，系统应先显示明确影响和可取消提示。不得在用户不知情时连续打开窗口。

## 8. 结果语义

任务状态统一为：

- `queued`：等待执行；
- `running`：正在执行；
- `waiting_user`：需要登录、授权或允许前台操作；
- `completed`：请求范围完整完成；
- `partial`：已获得部分结果，并说明缺失项；
- `failed`：没有可用结果；
- `cancelled`：用户取消。

数据结果必须包含：

- 规范资源身份；
- 字段值及字段级来源；
- 抓取时间和新鲜度；
- 身份证据强度；
- 请求字段和实际字段覆盖率；
- 分页游标、覆盖范围和 `exhausted`；
- Provider 尝试摘要和可复制诊断 ID。

## 9. 非功能要求

以下是目标值，需要在基准集上校准：

### 9.1 正确性

- 文章和公众号错误归属率必须为 0；不确定时返回失败或等待确认。
- `0` 与未知值严格区分。
- 同一规范文章的不同来源结果可合并，但必须保留字段级 provenance。

### 9.2 性能

- 新鲜本地缓存命中：p95 小于 500 ms。
- 普通文章正文网络获取：p95 小于 3 秒。
- 后台互动数据 Provider：阶段目标 p95 小于 10 秒。
- 公众号同步：首批结果目标小于 5 秒，后续分页后台继续。
- 界面操作不得因长任务阻塞；所有超过 1 秒的采集都应进入任务模型。

### 9.3 可靠性

- 公众号分页任务可恢复、幂等、可取消。
- App 或 Provider 异常退出后不得重复写入文章。
- Provider 失败不得破坏已存在的正确数据。
- 同一前台 Provider 在同一时刻最多执行一个任务。

### 9.4 隐私与安全

- 微信、公众号后台和第三方凭证默认只保存在本机安全存储。
- 日志不得记录 Cookie、授权 URL、完整会话令牌或正文私密数据。
- 远程 Provider 必须显式说明会发送哪些输入，默认可禁用。
- Sidecar Provider 使用能力授权，不能默认读取整个用户目录。

### 9.5 可观测性

- 每个任务拥有稳定的 `job_id`。
- 每次 Provider 尝试记录耗时、结果状态、字段覆盖和结构化失败码。
- 产品层错误文案与诊断信息分离；用户可复制诊断 ID。

## 10. 产品成功指标

- 三类核心任务的端到端成功率。
- 互动数据身份正确率与字段完整率。
- 公众号同步覆盖率和恢复成功率。
- 默认流程中需要人工操作的次数。
- 默认流程抢占微信前台的比例。
- 从输入到首个可用结果的 p50、p95。
- 从文章筛选到生成带引用分析结果的完成率。
- 监控任务的新文章发现延迟和重复率。

## 11. MVP 验收范围

第一版新内核必须完成：

1. 三类统一采集请求。
2. Provider Registry、Manifest、健康检查和自动路由。
3. 将现有实现包装为 Provider，不要求第一阶段提高其成功率。
4. 统一 Job、Attempt、结果和 provenance 模型。
5. 原界面可在 Feature Flag 下调用新内核。
6. 完成固定基准集上的 Provider 评测报告。

数据集、Agent 和监控在内核稳定后分阶段进入，不阻塞三类核心采集能力落地。
